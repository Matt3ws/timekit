TL;DR #

Vi erstatter tauri-plugin-sql med libsql embedded replica. Hver maskine får en lokal kopi af databasen, så læsning er hurtig og virker offline. Alle ændringer sendes direkte til én fælles Turso-database. Det betyder ingen konflikter, og fakturanumre kan ikke blive dubleret. Uden opsætning kører appen lokalt præcis som i dag. Turso-URL og token sættes i Settings → Synkronisering. Gratisplanen dækker rigeligt (5 GB, 10 mio. skrevne rækker om måneden).

Baggrund #

Valgt: altid online-skriv

valgt

libsql-craten (SQLite-fork, produktionsklar). Læsning sker lokalt, skrivning går til Turso, og den lokale kopi opdateres bagefter.

Tradeoff: Det kræver internet at starte en timer eller oprette en faktura. Til gengæld virker alle eksisterende migrationer uændret, fordi det er rigtig SQLite.

Fravalgt: fuldt offline (Turso Sync)

turso-craten med push/pull. Den bruger ny Rust-motor, og konflikter løses med "sidste push vinder".

Fravalgt fordi: to maskiner offline kan udstede samme fakturanummer, og motoren mangler stadig dele af SQLite.

Arkitektur & dataflow #

Uden opsætning bruger samme Rust-kode Builder::new_local("timekit.db"), så appen kører lokalt som i dag på den eksisterende fil.

Settings → Synkronisering #

Sync
Share one database between your Mac and PC via Turso.
Synced · last sync 4 s ago

Kortet bruger samme komponenter som det eksisterende BackupsCard: Card, Input, Label og Button. Teksten er på engelsk som resten af appen.

Indstillingerne gemmes i sync.json i appens config-mappe. De gemmes ikke i databasen, for så skulle tokenet bruges til at hente sig selv. Ændringer kræver genstart, fordi databasen åbnes ved opstart.

Statusprikken viser Local only, Synced eller Offline (read-only). Den kommer fra en sync_status-kommando.

Nøglekode #

src-tauri/src/db.rs — åbn databasen
let db = match sync_config::load(&app)? {
    // Ingen opsætning: præcis som i dag, samme fil.
    None => libsql::Builder::new_local(data_dir.join("timekit.db")).build().await?,
    // Turso: lokal replika, skrivninger går til primæren.
    Some(cfg) => libsql::Builder::new_remote_replica(data_dir.join("timekit-sync.db"), cfg.url, cfg.auth_token)
        .sync_interval(Duration::from_secs(15))
        .read_your_writes(true)
        .build()
        .await?,
};
let conn = db.connect()?;
migrate::run(&conn).await?;
src/db/client.ts — Drizzle taler med Rust i stedet for plugin-sql
export const db: SqliteRemoteDatabase<typeof schema> = drizzle(
  async (sql, params, method) => {
    const rows = await invoke<unknown[][]>("db_query", { sql, params });
    return { rows: method === "get" ? (rows[0] ?? []) : rows };
  },
  async (queries) => {
    await invoke("db_batch", { statements: queries.map(({ sql, params }) => ({ sql, params })) });
    return queries.map(() => ({ rows: [] }));
  },
  { schema },
);

Det skal du selv gøre #

Jeg må ikke oprette konti eller håndtere dit token, så de her trin skal du selv tage. Du skal først bruge dem ved trin 7:

  1. Opret en gratis konto på turso.tech. Det kræver ikke kreditkort.
  2. Opret en database i dashboardet, for eksempel timekit, i en EU-region.
  3. Kopiér databasens URL (libsql://…) og opret et auth-token til den.
  4. Indsæt begge dele i Settings → Sync i appen. Turso CLI kører ikke direkte på Windows, så web-dashboardet er nemmest.

Åbne spørgsmål #

  • Opstart uden internet: det er uvist, om new_remote_replica(...).build() fejler, når der ikke er net, selv om replikaen findes. Hvis den gør, åbner vi replikafilen lokalt som skrivebeskyttet og viser "Offline (read-only)". Afklares i trin 7.
  • Kvitteringsfiler (bilag) synkroniseres ikke. Udgifter gemmer en sti til en fil i appdata, og den fil findes ikke på den anden maskine. Udgiften synkroniseres, men billedet gør ikke. Det kan løses senere ved at gemme bilag i databasen (der er 5 GB gratis). Uden for denne plan.
  • Backup i sync-tilstand: VACUUM INTO skal køre på en separat lokal forbindelse til replikafilen, ikke gennem replikaen, der ville sende den til Turso. Det skal testes. Kan det ikke lade sig gøre, laver vi en sync og kopierer derefter filen. Turso har desuden 1 dags point-in-time restore på gratisplanen.
  • Inaktivitet på gratisplanen: Turso har tidligere sat gratis databaser på pause efter en periode uden brug. Det fremgår ikke af prissiden lige nu. Hvis det sker, vækker første opkald den igen.
